# Number Provenance

Every metric in the `README.md` was sourced dynamically from the pipeline's final SQLite database (`data/regime_store.db`) after a complete out-of-sample walk-forward run.

### Data Sources
1. **Headline Metrics (CAGR, Vol, Sharpe, Max DD, VaR, CVaR):**
   - Queried directly from `SELECT * FROM backtest_metrics WHERE cycle='full'`.
   - These are generated by `src/backtest/metrics.py` and written to the DB by `scripts/backfill_db.py`.
2. **Buy-and-Hold Benchmarks:**
   - Generated by comparing the strategy returns against the raw price series in `notebooks/03_backtest_and_risk.ipynb` and `notebooks/04_sql_analysis.ipynb`.
3. **Bootstrap P-Values:**
   - Calculated using 1,000 resamples of the paired return series. (Script: `scratch/get_final_stats.py`).
4. **Per-Cycle Breakdown:**
   - Sourced from the explicit SQL CTE in `notebooks/04_sql_analysis.ipynb` mapping standard historical dates to the daily returns in `backtest_daily`.
5. **Detection Lag:**
   - Evaluated by tracking the first day a 'Crisis' label was emitted in 2008 and 2020. (Script: `scratch/get_final_stats.py`).
6. **Feature Correlation / Ablation:**
   - Evaluated empirically during Phase 2 (correlation between Trend/MACD and Momentum/RSI).

### Conclusion Validation
The numbers honestly reflect that while the HMM successfully acts as a risk-off filter that severely truncates tail-risk drawdowns (cutting SPX Max Drawdown from ~56% to ~22%), the combined drag of detection lag (trailing smoothing), false-positive transitions, and transaction costs prevents it from generating absolute alpha. It systematically underperforms passive Buy & Hold on a risk-adjusted (Sharpe) basis across all evaluated assets.
